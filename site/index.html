A real run, recorded

The README describes this as a full rehearsal on a live AKS cluster: deploy, a failed CI run, a bad tag and rollback, promotion, drift, self-heal, prune and a sealed secret.

Decisions worth knowing

ChoiceWhy
One AKS cluster, two namespacesA second cluster roughly doubles the bill. The cost is a shared node and shared blast radius, which the README says it would not accept for real prod.
Image tag is sha-<commit>Immutable and traceable. The /version endpoint reports the same value.
dev on every merge, prod on approvalThe promote workflow waits on the production environment reviewers, then commits the tag.
Sealed SecretsFree, and encrypted values live in Git. The key pair is kept in Pulumi config so a rebuilt cluster can still decrypt.
Pulumi in GoSame language as the app, real types, ordinary functions for reuse.
No ingress, no Log AnalyticsEach adds an hourly or per-GB charge. Port-forward and logs are enough for a demo.

Run it on your own subscription

Needs az, pulumi, kubectl, kubeseal, gh, Go 1.25+ and an Azure subscription. It creates billable resources, so tear it down after.

az login
cd infra && pulumi login && pulumi stack init demo && cd ..
scripts/gen-sealing-key.sh
make preview
make up
make status
make argocd-ui
make down   # removes everything

See also argocd-gitops for the wider multi-cluster patterns.

What this does not do
  • The walkthrough above is a simulation. It shows the flow, it does not talk to a cluster.
  • One cluster with two namespaces is a demo layout, not a production isolation model.
  • Only pulumi preview has been run for the dev and prod stacks. Neither has been applied.
